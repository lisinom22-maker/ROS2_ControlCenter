ROS 2 控制中心使用说明
=====================

这个程序解决什么问题
------------------
刚开始使用 ROS 2 时，创建工作空间、建功能包、选择依赖、打开源码、构建和运行节点通常分散在多个终端和命令中。控制中心把这些常见操作集中到一个窗口，让你看得见当前选择的工作空间、文件夹、功能包和运行结果。具体的节点代码仍在 VS Code 中由你编写。

它能做什么
----------
• 创建和切换多个工作空间；在 src 下选择或新建不同名字的代码文件夹。
• 创建 Python 或 C++ 功能包、生成示例节点，并勾选已安装的常见 ROS 依赖。
• 选中源码后自动用 VS Code 打开；选择整个工作空间或指定功能包构建，再运行、停止节点并查看输出。
• 查看 ROS 节点、话题、服务，以及话题消息；启动和停止小乌龟、RViz2、rqt 等工具。

首次使用前的准备
----------------
1. 使用 Ubuntu 22.04 图形桌面，并安装 ROS 2 Humble。控制中心当前固定使用 Humble；确认 /opt/ros/humble/setup.bash 存在。
2. 安装系统组件：python3-pyqt5、python3-colcon-common-extensions、gnome-terminal、nautilus。缺少时在终端执行：
   sudo apt update
   sudo apt install python3-pyqt5 python3-colcon-common-extensions gnome-terminal nautilus
   如果提示找不到 python3-pyqt5，先启用 Ubuntu Universe 软件源。若 apt 提示锁被其他进程占用，等待它结束后重试，不要删除锁文件。
3. 安装 VS Code，并在终端输入 code --version 确认能调用。写 Python 建议装微软 Python 扩展；写 C++ 建议装微软 C/C++ 扩展。扩展只提供编辑辅助，控制中心的构建和运行不依赖这些扩展。
4. 写 C++ 还需要系统编译工具，例如 sudo apt install build-essential。勾选 ROS 库之前，须先安装对应的 ROS 2 软件包；勾选库不会替你联网安装。
5. 双击桌面“ROS2 控制中心”图标。若系统提示图标不受信任，右键选择“允许启动”。首次使用建议先创建一个新工作空间。

从创建到运行：按哪里
------------------
1. 工作空间：点“按名称新建…”，输入名字（如 my_robot_ws）并确定，程序创建 ~/my_robot_ws/src。已有工作空间可从“已用过”切换，或点“选择工作空间…”选择目录。不同工作空间可以分别保存不同项目。
2. 写代码位置：默认是当前工作空间的 src。点“创建文件夹…”输入名称并确定，会在当前文件夹中新建并选中；点“选择文件夹…”可进入已有文件夹。“打开此文件夹”会用 VS Code 打开它。
3. 功能包：点“设置并创建功能包…”，输入包名，选择 Python 或 C++，按需要勾选已安装的 ROS 库，再点“创建功能包”。包会建在当前选中的文件夹内，并生成示例节点。包名须以小写英文字母开头，只能包含小写字母、数字和下划线。
4. 编写：新包的示例源码会自动在 VS Code 打开。修改代码后按 Ctrl+S 保存。以后可点“选择源码文件…”打开别的文件，或点“编辑选中包源码”重新打开示例源码。
5. 构建：先确认上方“路径”是要编译的工作空间；再从“编译目标”下拉框选择“整个工作空间”或一个功能包。列表只显示当前工作空间中的包；新建或修改包后可点“刷新功能包”。选单个包会同时构建它在当前工作空间内的依赖包，已安装在系统里的 ROS 库无需重新构建。点“在终端构建”，等待终端显示 Summary 和成功结果；失败就回 VS Code 修改、保存，再构建一次。不要用 VS Code 的“运行 Python 文件”代替 ROS 节点构建。
6. 运行：构建成功后点“刷新可运行节点”，从列表选中节点，再点“运行节点”。输出在控制中心显示；点“停止节点”结束当前节点。
7. 看话题：如果你的代码发布了话题，先运行节点，在话题框输入实际名称（如 /chatter），点“查看话题”。新终端中按 Ctrl+C 停止查看。示例节点不一定发布话题。

常用工具和注意事项
------------------
• 上方工具卡可启动、停止或重新启动常用 ROS 工具。“停止全部”只管理控制中心启动的工具；已打开的文件夹、构建终端、话题终端需各自关闭。
• 关闭控制中心会停止由当前窗口运行的节点；构建完成后若列表没更新，点“刷新可运行节点”。
• 切换工作空间后，再确认编译目标、文件夹、功能包和节点是否属于当前工作空间。创建功能包时可勾选本机已安装的常见 ROS 库；这些依赖会写入 package.xml。修改已有功能包的依赖仍需在 VS Code 中编辑 package.xml 和源码。所选 ROS 库必须已经安装；“系统状态监控”是可选的独立项目，缺少它不影响工作空间功能。
• 控制中心负责准备和执行常见操作，不会自动写出你的业务逻辑。保存代码、构建和运行是三个不同动作。
